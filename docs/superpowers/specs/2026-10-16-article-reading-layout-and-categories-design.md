# 文章阅读布局与分类管理设计

## 背景与目标

现有文章页仅展示居中的正文，文章之间缺少结构化导航，长文章也没有章节定位和阅读进度反馈。本次改动将文章页调整为文档站式阅读布局，并在管理后台增加文章分类和手动排序能力。

完成后的桌面文章页由三栏组成：左侧是按分类组织的文章导航，中间是当前文章正文，右侧是当前文章目录和环形阅读进度。设计同时适配日间、夜间和较窄屏幕，并保留现有评论、划词批注、代码高亮、主题切换与访问统计能力。

## 范围

本次包含：

- 分类的创建、改名和删除。
- 每篇文章归属零个或一个分类。
- 分类和分类内文章的手动排序。
- 文章页左侧分类文章导航。
- 文章页右侧二、三级标题目录、当前章节高亮和环形阅读进度。
- 日间、夜间和响应式布局。
- 数据库迁移、管理员 API、后台管理界面及相关测试。

本次不包含：

- 多分类或标签系统改造。
- 在后台创建、编辑或删除 MDX 正文。
- 分类独立详情页、分类 SEO 页面或公开分类 API。
- 拖拽排序。手动排序使用明确的上移和下移操作，避免增加拖拽依赖和复杂交互。

## 数据模型

### `article_categories`

- `id`: UUID 主键。
- `name`: 分类名称，去除首尾空格后必须非空，大小写不敏感地唯一。
- `position`: 非负整数，决定左侧分类顺序。
- `created_at`、`updated_at`: 时间戳。

### `article_category_assignments`

- `post_slug`: 文章 slug，主键，确保一篇文章最多属于一个分类。
- `category_id`: 外键，引用分类。
- `position`: 非负整数，决定文章在分类内的顺序。
- `created_at`、`updated_at`: 时间戳。

删除仍有文章关联的分类时由业务层拒绝。数据库外键使用限制删除，作为第二道保护。未建立归类记录的 MDX 文章属于虚拟的“未分类”分组；该分组不写入分类表，始终显示在真实分类之后，其中文章按发布日期倒序、slug 作为稳定次级排序。

分类或文章移动后，所属列表的位置将重新规范为从零开始的连续整数，避免长期操作产生重复或稀疏位置。

## 数据读取与合并

MDX 文件继续作为文章正文和标题、日期、摘要等元数据的唯一来源。数据库只保存分类、归属关系和展示顺序，不复制正文元数据。

服务端导航查询按以下步骤工作：

1. 使用现有文章读取函数获得所有实际存在的 MDX 文章。
2. 查询分类及文章归类记录。
3. 忽略数据库中指向已不存在 MDX 文件的孤立 slug，避免显示死链接。
4. 按分类和文章位置生成导航分组。
5. 将没有有效归类记录的文章放入“未分类”。

公开文章页读取分类数据失败时，降级为单个“全部文章”分组并按发布日期倒序展示。正文渲染不依赖分类数据库成功，因此分类服务异常不会阻止用户阅读文章。后台不静默降级，而是展示可重试的错误状态。

## 管理后台

管理中心增加“文章分类”入口。分类管理页沿用现有后台的管理员会话验证。

页面分为两部分：

1. 分类列表：创建分类、修改名称、上移、下移、删除空分类。
2. 文章归类列表：展示所有 MDX 文章、当前分类和当前顺序；可通过分类选择器改变归属，并在当前分类中上移或下移。

移入新分类的文章默认追加到该分类末尾。移回“未分类”会删除归类记录。删除非空分类、重复名称、空名称、不存在的文章 slug、无效 UUID、无效移动方向或越界操作均返回明确错误，界面通过 toast 展示结果并在成功后刷新当前数据。

管理员 API 采用资源化路由，并对每个写操作执行现有的管理员登录验证。业务规则集中在 service 层，路由只负责认证、解析输入和映射响应，数据库访问集中在 repository 层。

## 前台文章页

### 桌面布局

在宽屏上使用三栏网格：

- 左栏约 260px，展示分类和文章导航。
- 中栏最大约 800px，展示正文。
- 右栏约 240px，展示目录和阅读进度。

左右栏在文章滚动期间保持可见，各自内容过长时允许独立滚动。中栏延续现有 Typography、代码块、表格和图片的自适应规则。

左侧当前文章只使用符合主题的黑白灰状态，不使用蓝色：

- 日间模式使用浅灰背景、近黑文字和深灰强调。
- 夜间模式使用深灰背景、白色文字和浅灰强调。

分类名称作为分组标题，文章顺序完全遵循后台配置。当前文章使用 `aria-current="page"`，侧栏和目录均提供清晰的键盘焦点状态。

### 目录与章节高亮

客户端目录组件读取正文区域中的 `h2` 和 `h3`：

- 为标题生成稳定、去重的锚点 ID；已有 ID 时保留。
- 二级标题正常显示，三级标题缩进显示。
- 点击条目时平滑滚动到标题；用户启用减少动态效果时改为即时滚动。
- 监听现有页面滚动容器，根据各标题相对视口顶部的位置计算当前章节，并以蓝色文字和左侧蓝色指示线高亮。
- 没有二、三级标题时隐藏目录列表。

### 环形阅读进度

“目录”标题右侧显示紧凑的 SVG 环形进度：灰色底环和蓝色进度弧。进度以正文区域为基准，而不是整个站点页面：正文顶部到达阅读视口时从 0% 开始，正文底部进入已读范围时到达 100%。数值限制在 0% 到 100%，通过 `requestAnimationFrame` 合并高频滚动更新。

环形组件包含可访问名称和当前百分比信息，但视觉上不强制显示数字，保持参考图中的轻量效果。

### 响应式行为

视口宽度达到 1280px 时显示完整三栏。低于 1280px 时，左右侧栏不再占据固定列，改为正文上方的两个原生可折叠面板：“文章导航”和“本文目录”。折叠内容继续支持当前项状态、目录跳转和环形进度。移动端正文保持全宽并保留合适的水平留白。

## 组件与模块边界

- `lib/posts`: 扩展文章摘要读取能力，并提供导航合并所需的稳定文章数据。
- 分类 repository：只处理分类和归类关系的 SQL。
- 分类 service：执行名称校验、文章存在性校验、归类和连续排序规则。
- 管理员 API：认证、请求校验和 HTTP 响应。
- 分类管理组件：加载状态、错误状态、分类操作和文章操作。
- `ArticleNavigation`: 渲染分类文章导航，不负责取数。
- `ArticleTableOfContents`: 发现标题、生成锚点并维护当前章节。
- `ReadingProgressRing`: 只负责把归一化进度渲染为圆环。
- `ArticleReadingLayout`: 组合桌面三栏和窄屏折叠布局，并提供正文引用。

组件之间传递明确的数据结构，目录和阅读进度不依赖分类模块，分类管理也不接触 MDX 渲染细节。

## 主题与视觉规则

颜色优先使用现有 CSS 变量和 Tailwind 深色变体，不在组件内判断主题。边框、背景、正文、次要文字和悬停状态在日间与夜间分别保持足够对比度。

蓝色只用于右侧目录当前章节、可交互链接和进度弧。左侧当前文章严格采用黑白灰。所有动画遵守 `prefers-reduced-motion`。

## 缓存与更新

文章正文仍由本地 MDX 动态导入。文章页使用动态渲染读取分类导航，确保后台修改在下一次页面请求时可见，避免服务端缓存与直接数据库查询组合后出现难以验证的过期数据。个人博客的访问规模可以接受每次文章请求增加一次轻量分类查询。

## 测试与验收

自动化测试至少覆盖：

- 分类名称校验、唯一性和非空分类删除保护。
- 单文章单分类约束，以及分类和文章移动后的连续排序。
- MDX 文章与数据库记录的合并、未分类分组、孤立 slug 忽略和数据库失败降级。
- 管理员 API 的未登录响应、非法输入、冲突和成功路径。
- 标题 ID 的稳定生成与重复标题去重。
- 二、三级目录层级、当前章节切换和目录点击。
- 阅读进度在顶部、正文中间、底部以及极短正文上的计算。
- 左侧当前文章的日间和夜间主题类不包含蓝色状态。
- 窄屏折叠面板和宽屏三栏的渲染。
- 现有评论、划词批注和访问追踪在新正文容器中仍正常挂载。

完成前运行完整 Vitest、ESLint 和生产构建。随后在真实浏览器中检查至少一个长文章和一个短文章，分别验证日间、夜间、桌面和移动宽度，确认侧栏滚动、目录跳转、章节高亮和环形进度表现。

## 成功标准

- 管理员可以不修改代码地创建分类、为文章选择唯一分类并手动调整分类和文章顺序。
- 所有 MDX 文章始终能在左侧导航或降级导航中找到。
- 宽屏文章页与参考图具有一致的文档阅读信息层级。
- 左侧当前文章状态在两种主题中均为黑白灰；右侧目录高亮和进度弧为蓝色。
- 目录准确反映二、三级标题，当前章节和阅读进度随正文滚动更新。
- 较窄屏幕不因三栏布局压缩正文。
- 数据库或分类读取异常不会导致文章正文不可访问。
